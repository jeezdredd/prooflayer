# System Audit 2026-08

Full-stack audit pass. Test baseline went from **33 failed / 133 passed** to **301 passed**.

## Detection correctness

### Aggregator dropped signal (highest impact)
`PROBABILISTIC_ANALYZERS` was a hardcoded name set. Consequences:
- `llm_vision` was in the set but never emits `ai_probability` -> skipped by the probability
  loop and excluded from the rule-based loop -> **zero weight in every score**, while still
  counting as a corroborating voter.
- `custom_detector` (weight 3.5, the highest) and `ai_detector` were **not** in the set, so
  their real probabilities were discarded and replaced by 0.0/0.5/1.0 verdict buckets.

Now sourced from evidence: `PROBABILITY_KEYS = ("ai_probability", "ai_probability_avg")`,
clamped to `0..1`, non-numeric falls back to the verdict bucket. See [[concepts/aggregation]].

### EXIF sub-IFD never read
`content/services.extract_metadata` called `img.getexif()`, which returns **IFD0 only**.
Every capture field the [[analyzers/metadata]] analyzer checks - `ExposureTime`, `FNumber`,
`ISOSpeedRatings`, `FocalLength`, `LensModel` - lives in the Exif sub-IFD (`0x8769`).
Verified empirically: a real camera JPEG yielded `['ExifOffset', 'Make', 'Model']`.
So `capture_fields_present` was always `0` and `has_camera_signature` **could never be true**.
Fixed by merging `get_ifd(0x8769)`. Also `DateTimeOriginal` was invisible to the date check.

### GPS check was dead
`extract_metadata` writes GPSInfo keys as `str(k)`, but `_check_gps_plausibility` looked them
up with `int` keys. Now accepts both.

### video_frame unreachable branch + GPU crash
- `if ai_prob >= 0.65: suspicious` came **before** `elif ai_prob >= 0.85: fake` -> the `fake`
  verdict was unreachable; every AI frame capped at `suspicious`.
- `_analyze_frame` fed CPU tensors into a CUDA/ROCm-resident model (no `inputs_to_device`) ->
  every frame raised, got swallowed, and the analyzer reported `frames_analyzed: 0`.
  **Video analysis was fully broken on the GPU worker.**
- Sampling read frames sequentially at stride 30 with `MAX_FRAMES=8` -> only the first ~8
  seconds of any video were ever seen. Now seeks across the whole duration.
- Emits a top-level `ai_probability` (median over frames) so it feeds the weighted mean.

### community_forensics preprocessing
`.resize((384, 384))` distorted aspect ratio and resampled away the high-frequency generator
fingerprints the detector keys on. Now: letterboxed global view + a **native-resolution
center crop** when the image is large enough, averaged. See [[analyzers/community-forensics]].

### custom_detector
Ran on **CPU only** (never called `_device`) despite carrying the highest weight, and read
`probs[-1]` blindly instead of consulting `id2label`. Today `Nahrawy/AIorNot` happens to be
`{0: real, 1: ai}`, so it worked by luck - a retrain emitting a different label order would
have **silently inverted** it. Now label-aware with a logged fallback.

### ai_detector was dead code
`clip_detector.AIImageDetector` was missing from `seed_analyzers.ANALYZERS`, so the stale-config
sweep **deactivated it**. Re-seeded (weight 1.5). Also `_MAX_CACHED = 1` with a 2-model
ensemble evicted and reloaded both models on every single image; now sized to the ensemble.

### C2PA never worked
`c2pa.read_file` was removed when c2pa-python moved to the stream-based Reader API in 0.5.0,
but `pyproject` pins `>=0.6`. Every call raised and was swallowed -> Content Credentials were
never extracted. `read_c2pa_manifest()` now tries `Reader` -> `c2pa_api.Reader` -> legacy.

The manifest is now read **during** `process_submission` and stored at `metadata["c2pa"]`, so
the metadata analyzer can act on it. A declared `trainedAlgorithmicMedia` digitalSourceType is
the strongest available signal and returns `fake` at 0.95 confidence.

### Metadata analyzer signal coverage
- Generator list was stuck in 2023: no Flux, SDXL, Ideogram, Imagen, Sora, gpt-image, ComfyUI,
  Automatic1111, Firefly variants. Extended.
- PNG `parameters` / `prompt` / `workflow` text chunks (where A1111 and ComfyUI write the full
  generation config) and XMP were **never parsed**. Now extracted in `extract_metadata` and
  matched against both the generator list and sampler/CFG/steps markers.
- Camera EXIF alone previously returned `authentic` at **0.85** confidence. EXIF is trivially
  forged, so a spoofed `Make`/`Model` bought a strong authentic vote. Lowered to 0.55.

### Weight rebalance
`custom_detector` held the highest weight (3.5) while defaulting to a weak 2022-era base model;
`metadata` held 2.5 despite being the most forgeable input. Per the 2026 benchmark
(Community-Forensics best overall at 75% mean, ensembles dominate):

| analyzer | before | after |
|---|---|---|
| community_forensics | 3.0 | **3.5** |
| siglip_detector | 2.0 | 2.0 |
| npr_detector | 0.5 | 1.0 |
| custom_detector | 3.5 | **1.5** |
| ai_detector | *(dead)* | **1.5** |
| metadata | 2.5 | **1.5** |
| ela | 1.0 | **0.75** |

## Security

### SSRF: DNS rebinding (TOCTOU)
`validate_public_url` resolved the host with `gethostbyname`, then `requests` resolved it
**again** for the actual connection. An attacker-controlled record with a short TTL answers
public on the first lookup and `169.254.169.254` on the second. Also `gethostbyname` is
IPv4-only, so it never saw AAAA answers.

Now `getaddrinfo` validates **every** address (v4 + v6 + IPv4-mapped), and `safe_get` pins the
validated set for the duration of the request via a thread-local `getaddrinfo` override.
Blocking also switched to `not is_global` **plus** the explicit flags - `is_global` alone lets
multicast through. See [[fixes/ssrf-guard]].

### Upload memory exhaustion
`FILE_UPLOAD_MAX_MEMORY_SIZE = DATA_UPLOAD_MAX_MEMORY_SIZE = 500MB` meant Django buffered a
whole 500 MB upload **in RAM** instead of spooling to disk. A handful of concurrent uploads
OOMs the backend. Now 5 MB / 10 MB; `MAX_UPLOAD_SIZE` stays 500 MB.

### IDOR on submission status
`SubmissionStatusView` was `AllowAny` with `authentication_classes = []` and returned status,
verdict and score for **any** submission id. Now requires public, owned, staff, or an
anonymous `analyze-url` submission (which must stay pollable).

## Reliability

- **Provenance ran twice per submission**: `scan_provenance` in `process_submission` and again
  in `run_provenance_check` after aggregation, duplicating pHash and C2PA rows. The post-verdict
  task is now external-API only (TinEye, Google Vision); C2PA extraction is idempotent.
- **weasyprint import broke the whole URLconf**: `factcheck/pdf.py` imported it at module level,
  so a missing native `gobject` made `config.urls` unimportable - every view test errored out.
  Made lazy, matching `content/pdf.py`.
- **Cache bled across tests**: throttle and quota counters live in shared Redis, so later tests
  got spurious 429s. Autouse fixture in `backend/conftest.py` clears it.

## Second pass

### Media was world-readable
`AWS_DEFAULT_ACL = "public-read"` with `querystring_auth: False` made **every** uploaded file
readable by anyone with the URL, regardless of the `is_public` toggle. Now `MEDIA_PRIVATE`
(default on) sets a private ACL and presigned URLs; `custom_domain` is dropped in that mode
because a CDN alias cannot carry the signature.

Knock-on: `ela_analyzer` stored `default_storage.url(...)` **inside the evidence JSON**, so a
presigned link would rot after an hour. Evidence now stores `heatmap_path` and
`AnalysisResultSerializer` re-signs it on read. The frontend contract (`evidence.heatmap_url`)
is unchanged.

### Widget was an unthrottled hash oracle
`WidgetEmbedView` had `throttle_classes = []` and matched **any** completed submission by
sha256, private ones included. Now scoped to `is_public=True` and throttled at 120/hour.

### Anonymous submissions landed in an admin's account
`AnalyzeUrlView` used `User.objects.filter(is_staff=True).first()` as the owner. Replaced with
a dedicated `anonymous@prooflayer.invalid` service account, created inactive with an unusable
password, so anonymous traffic cannot pollute a real admin's list or quota.

### Retrain would OOM and leak
`_finetune` materialized every preprocessed tensor into a Python list (~600 KB per image, so
several GB on any realistic set) - now a lazy `TorchDataset` that decodes in `__getitem__`.
The train/eval split was per-file, so **8 frames of one video straddled both sides**; splitting
is now by source group (`_sample_group` strips the `_f<idx>` / `_spec` suffix). `media_type`
was hardcoded to `"image"` inside `_finetune`, ignoring the caller. `AutoFeatureExtractor`
(deprecated) swapped for `AutoImageProcessor`.

### Double aggregation
`rescue_stuck_submissions` could fire `aggregate_verdicts` while the chord callback was already
running. Guarded with an atomic `cache.add` lock (`aggregating:<id>`, 600s) rather than a new
status column.

### Audio had no probability
`audio_spectrogram` emitted only a verdict, so it fell into the coarse bucket path. It now also
reports `ai_probability` derived from the flag count.

## Third pass (2026-09-04): real NPR

### The name was a lie
`npr_detector` ran `Wvolf/ViT_Deepfake_Detection`, a face-swap ViT that has nothing to do with
Neighboring Pixel Relationships. It now lives at [[analyzers/face-deepfake-detector]] (weight 0.5,
AUC 0.688 off-domain) and the real NPR (Tan et al., CVPR 2024) was implemented from the authors'
repo: ResNet-50 stem + layer1 + layer2 over `x - nearest_up(nearest_down(x))`, 1.44M params,
sha256-pinned checkpoint, `weights_only=True`, no resize at inference. Verified against the
authors' own demo images (midjourney logit +110, CelebAHQ -114). 24 unit tests.

### And then it measured as a coin flip
| analyzer | AUC | verdicts on 60 AI | verdicts on 60 real |
|---|---|---|---|
| npr_detector (real) | **0.499** | authentic 59, fake 1 | authentic 58, fake 2 |

The checkpoint is ProGAN-trained; diffusion samplers do not leave the nearest-neighbour
up-sampling residue it keys on. 58/60 AI images scored p<0.01. Worse, the logits saturate at
±100, so it is a *confident* wrong voter - together with the face ViT it manufactured
`needs_review` on **27/60 AI images** and dropped ensemble accuracy 1.000 -> 0.992.

Decision: **not seeded**. The module, tests and wiki page stay; it is a correct GAN-era detector
that can be re-enabled from the seed list if that threat matters. This is the benchmark's
headline finding reproduced locally: training-data alignment beats architecture.

### Head-count disagreement was the real bug
`needs_review` fired on any 2-vs-2 confident split regardless of weight. Two saturated,
out-of-domain detectors (1.0 + 0.5) could outvote CF 3.5 + custom 1.5 + ai_detector 1.5.
Replaced with a weight-share rule: both camps need >= 2 voters **and** the lighter camp must
hold >= 30% of the confident-voter weight. `CF_PRIORITY_PEERS` also gained `custom_detector`
and `ai_detector`; before, the only peer that could confirm a CF override was siglip at AUC 0.32.

### Final numbers, production roster
| true class | before NPR | with NPR (head count) | final (weighted rule, no NPR) |
|---|---|---|---|
| real | authentic 53, needs_review 7 | authentic 52, needs_review 8 | authentic **53**, needs_review 7 |
| ai | fake 42, likely_fake 5, inconclusive 13 | needs_review **27**, fake 16, inconclusive 12, likely_fake 4, suspicious 1 | fake **43**, likely_fake 4, inconclusive 13 |

Ensemble AUC 1.000 / acc 1.000. Suite: **341 passed**.

## Fourth pass (2026-09-04): modern generators

Everything above was measured on diffusiondb (2022 SD 1.x) vs flickr, which every current
detector separates perfectly. That says nothing about 2026. `fetch_openfake` pulled 150 real
LAION photos and 236 AI images across **20 current generators** (midjourney-7, gpt-image-1.5/2,
nano-banana-pro, flux.2-klein-9b, seedream-v5, sora-2, veo-3, recraft-v2/v3, ideogram-2,
z-image-turbo, wan-video-2.5, ernie-image, lumina, illustrious, aurora, halfmoon, frames) from
[OpenFake](https://huggingface.co/datasets/ComplexDataLab/OpenFake) (CC-BY-NC-4.0, local eval only).

### Before: the ensemble called 41% of modern AI "authentic"
| analyzer | AUC | acc@0.5 | mean_real | mean_ai |
|---|---|---|---|---|
| community_forensics | **0.977** | 0.588 | 0.001 | 0.351 |
| ai_detector | 0.723 | 0.638 | 0.479 | 0.627 |
| custom_detector | 0.670 | 0.645 | 0.324 | 0.585 |
| face_deepfake_detector | **0.181** | 0.319 | 0.359 | 0.138 |
| ENSEMBLE | 0.808 | 0.627 | | |

AI: fake 26, likely_fake 16, suspicious 46, inconclusive 47, **authentic 96**, needs_review 5.
Real: authentic 147, suspicious 3. This is the benchmark paper's headline reproduced locally
(Flux dev 21%, MJ v7 24% there).

### The diagnosis was calibration, not discrimination
CF's AUC on modern output is 0.977 - it still *ranks* AI above real almost perfectly - but its
raw sigmoid sits at median 0.32 on OpenFake vs 0.997 on diffusiondb, so the fixed bands
(fake >= 0.85, authentic < 0.35) read most of it as real. Meanwhile across **all 210 real photos**
the raw score never exceeds 0.147 (p99 = 0.0045). A threshold of 0.15 on CF alone gives
**0.0% FPR and 60.6% TPR** on OpenFake, versus 12.3% TPR at the old 0.85.

Shipped: a monotone piecewise-linear `calibrate()` on CF's raw output, knots
`(0, 0) (0.005, 0.20) (0.10, 0.55) (0.50, 0.75) (1, 1)`, applied before the bands and before
aggregation; `raw_probability` kept in evidence. Fitted on half the generators + diffusiondb and
tested on the other half in both directions: held-out AI-called-authentic 41% -> 31% and
38% -> 16%, real -> fake 0/150 every time, diffusiondb unchanged at 0 AI-called-authentic. The
shipped knots are the conservative side of the two held-out fits. See [[analyzers/community-forensics]].

### Two more face models out
`siglip_detector` (AUC 0.323, **35% false-positive rate** on real photos at p>=0.75) was one of the
two voters behind every real-photo `needs_review` on diffusiondb; removing it took those 7 -> 0
with no change on the AI side. `face_deepfake_detector` (AUC 0.181 on OpenFake) contributed
nothing measurable at weight 0.5. Both unseeded; modules kept. Active image roster is now
community_forensics 3.5, custom_detector 1.5, ai_detector 1.5, metadata 1.5, ela 0.75.

### After
| analyzer | AUC | acc@0.5 | mean_real | mean_ai |
|---|---|---|---|---|
| community_forensics (calibrated) | 0.979 | **0.785** | 0.013 | 0.549 |
| ENSEMBLE | **0.890** | **0.777** | | |

| set | true class | before | after |
|---|---|---|---|
| OpenFake | ai (236) | fake 26, likely 16, susp 46, inconcl 47, **authentic 96** | fake **61**, likely 3, susp 40, inconcl 75, **authentic 57** |
| OpenFake | real (150) | authentic 147, suspicious 3 | authentic 147, suspicious 2, inconclusive 1 |
| diffusiondb | ai (60) | fake 43, likely 3, inconcl 14 | fake **55**, likely 1, inconcl 4 |
| diffusiondb | real (60) | authentic 59, suspicious 1 | authentic 58, suspicious 2 |

Caught (fake + likely_fake) on modern AI: **18% -> 27%**; called authentic: **41% -> 24%**;
real called fake: 0 before and after. Suite: **376 passed**.

### The ceiling, per generator (caught = ensemble fake/likely_fake)
| generator | caught | CF mean (cal.) | | generator | caught | CF mean (cal.) |
|---|---|---|---|---|---|---|
| flux.2-klein-9b | **0%** | 0.065 | | gpt-image-1.5 | 33% | 0.627 |
| sora-2 | **0%** | 0.316 | | z-image-turbo | 33% | 0.521 |

Flux.2 and Sora-2 score ~0 raw on CF; no monotone map separates what the model scores like a

means a lone strong CF can never produce `fake`, only `suspicious`/`inconclusive`; on modern output

single-detector false positives and the real-photo tail says CF alone would be safe at ~0.15 -

## Fifth pass (2026-09-04): the retrain - Tribunal 1.1

### Protocol first
Training data: `dataset/openfake` (150 real / 236 AI) + `dataset/hf` (250 real / 500 AI). Test:
a second OpenFake pull at another row-group offset, **deduplicated** against the training tree
by perceptual hash (13 exact duplicates removed - the offset alone was not disjoint), giving
100 real / 145 AI across 20 generators the model never saw. Baseline measured on exactly that
set before training. See [[concepts/detector-evaluation]].

### The run
`retrain_detector --base-model buildborderless/CommunityForensics-DeepfakeDet-ViT --extra-dir
dataset/openfake --extra-dir dataset/hf --epochs 3`: 1,022 train / 114 held-out by source group,
class weights 1.41 / 0.77, horizontal flip, **130 seconds on MPS**. Two things had to be fixed
to get there: the local dev DB was unmigrated (`approved_for_training` column missing - now
`retrain_detector` falls back to `--extra-dir` when the Submission table is unavailable), and
the 250 macOS stub files in `dataset/hf/real` would have crashed the Trainer mid-epoch
(`_collect_extra` now verifies each image).

### Detector level, held-out
| custom_detector | AUC | acc@0.5 | flux.2 | gpt-image-2 | sora-2 | veo-3 |
|---|---|---|---|---|---|---|
| AIorNot fallback | 0.711 | 0.653 | 0.17 | 0.72 | 0.78 | 0.42 |
| retrained (CF backbone) | **0.993** | **0.943** | 0.91 | 0.998 | 0.83 | 0.83 |

### Ensemble level: the weights were the cap, then the rule was
With the retrained member still at weight 1.5 under the 1.0 rules: ensemble AUC 0.916 -> 0.991
but caught only 34 -> 51 of 145; flux.2 / gpt-image-2 / sora-2 / veo-3 stayed at 0% because
a lone fake voter is downgraded and CF outweighed it. Offline simulation over the eval JSON
with the real `aggregate()`:

| weights (cf / custom / ai) | rule | caught | AI -> authentic | real -> fake |
|---|---|---|---|---|
| 3.5 / 1.5 / 1.5 (1.0) | two voters | 51 (35%) | 19 | 0 |
| 3.5 / 3.5 / 1.0 | two voters | 51 (35%) | 4 | 0 |
| 3.0 / 3.5 / 1.0 | any single voter | 106 (73%) | 4 | **1** |
| 2.5 / 4.0 / 0.75 | any single voter | 133 (92%) | 4 | **1** |
| 3.5 / 3.5 / 1.0 | any single voter | 103 (71%) | 4 | 0 |
| **3.5 / 3.5 / 1.0** | **lone voter iff share >= 50% and p >= 0.9** | **103 (71%)** | **4** | **0** |

The retrained model puts 5 of 100 real photos above 0.75, so "any single voter" convicts a
real photo on most weight sets. The share + certainty form of the exception gets the same
recall on the only weight set that was safe, with zero false accusations. Shipped as
Tribunal 1.1; numbers in [[concepts/tribunal]].

### What it costs
Real photos called `suspicious`: 2 -> 8 of 100 (none `fake`). The retrained member shares its
backbone with community_forensics, so on generators CF already sees the two are correlated
and the ensemble is effectively a two-judge bench for those; the independence is on the
generators CF is blind to.

### Shipping
Model persisted at `~/.cache/huggingface/prooflayer-retrained/image` (83 MB, sha256
`719fc0d51962a0a6…`). `make ship-retrained` copies it into the worker's `hf_cache` volume
(untested against the server yet). `make seed-analyzers-server` applies the 1.1 weights.
Rebuild the ROCm worker for the code side (calibration, lone-voter rule).

## Still open

- The 7 real photos still landing in `needs_review` are a genuine split: `custom_detector` and
  `ai_detector` vote fake against CF. A labelled set with more real-photo variety would say
  whether those two need a higher authentic threshold.
- No labelled face-swap data in `dataset/`. `face_deepfake_detector` and `siglip_detector` are
  now unseeded on off-domain evidence; a face-swap set could bring one back with a real number.
- gpt-image-2, flux.2-klein-9b, veo-3, sora-2 are still under 30% caught: the retrained member
  sees them but community_forensics scores them near real and outweighs it. Options: retrain CF
  itself the same way, or add a second modern-trained member with a different backbone so the
  bench is not two copies of one opinion.
- The retrained model is a strong ranker but not calibrated (5% of real photos above 0.75). A
  calibration map like CF's, fitted on held-out real photos, would let its weight rise further.
- Only one retrain so far; `run_weekly_retrain` still defaults to the AIorNot base and does not
  pass `--extra-dir`. Wire the bootstrap corpora and the CF base into the scheduled path.
- `audio_spectrogram` thresholds remain hand-picked, not fitted to labelled data.
- Video and audio retrain runs write models that `custom_detector` never loads (it only reads
  `RETRAIN_MODEL_DIR/image` and only accepts image mimes).

## Measured results

`eval_detectors --dataset dataset/hf --limit 60` on 60 flickr photos vs 60 diffusiondb images
(CPU, 250 corrupt real files skipped):

| analyzer | n | AUC | acc@0.5 | mean_real | mean_ai |
|---|---|---|---|---|---|
| community_forensics | 120 | **1.000** | 1.000 | 0.000 | 0.874 |
| custom_detector | 120 | 0.920 | 0.833 | 0.316 | 0.921 |
| ai_detector | 67 | 0.914 | 0.821 | 0.417 | 0.759 |
| npr_detector | 120 | 0.688 | 0.608 | 0.104 | 0.273 |
| siglip_detector | 120 | **0.323** | 0.500 | 0.689 | 0.633 |
| ENSEMBLE | 120 | **1.000** | 1.000 | | |

Two findings came out of this that no unit test would have caught:

### siglip_detector is anti-correlated
AUC **0.323** - below 0.5, so it ranks real photos as *more* AI-like than AI images
(`mean_real 0.689 > mean_ai 0.633`). `prithivMLmods/Deep-Fake-Detector-v2-Model` is a face
deepfake model, and this set is landscapes and art. Weight cut 2.0 -> 0.5. Not removed: the
benchmark's central finding is that detector rankings swing wildly across datasets, so one
dataset is not grounds for deletion - but it is grounds for not trusting it at weight 2.0.

### ELA was inverted on the axis it was weighted for
Measured over the same 120 images:

| | fake | suspicious | inconclusive | authentic |
|---|---|---|---|---|
| real photos | 11 | 27 | 20 | 2 |
| AI images | 2 | 10 | 40 | 8 |

**38/60 real photos called fake-or-suspicious against 12/60 AI images.** The
`uniformity_ratio < 0.3 and mean_error < 5.0 -> fake @ 0.85` rule fires on ordinary
high-quality JPEGs, while re-encoded diffusion output shows *higher* ELA error and reads as
"authentic". This was the source of the false `authentic_edited` verdicts.

ELA measures **recompression locality** (splicing), not synthesis. It now returns
`inconclusive` on the AI axis - which keeps it out of `DECISIVE_VERDICTS` and therefore out of
the weighted mean entirely - and reports `manipulation_suspected` / `block_outlier_ratio` in
evidence instead. `_has_manipulation_signal` reads that flag. The old tests accepted
`output.verdict in ("fake", "suspicious", "inconclusive")`, which is exactly why the inversion
survived.

### Ensemble verdict distribution, before vs after

| true class | before | after |
|---|---|---|
| real | authentic **17**, needs_review 21, authentic_edited 21, suspicious 1 | authentic **53**, needs_review 7 |
| ai | fake 36, likely_fake 11, inconclusive 10, needs_review 3 | fake **42**, likely_fake 5, inconclusive 13 |

False `authentic_edited` went 21 -> 0 and clean `authentic` on real photos 17 -> 53, with the
ensemble AUC unchanged at 1.000.

## Evaluation harness

`manage.py eval_detectors --dataset <dir> --limit N` runs the image analyzers plus the real
aggregator over a `real/` + `ai_generated/` tree and reports per-analyzer AUC, accuracy at 0.5,
mean score per class, error count and seconds/image, then the ensemble verdict distribution.
Unreadable files are skipped and counted. See [[concepts/detector-evaluation]].
